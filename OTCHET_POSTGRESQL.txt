2. ГДЕ ЧТО ЛЕЖИТ
--------------------------------------------------------------------------------

  Что                    Где                              Как
  ---------------------  -------------------------------  -------------------------
  Заказы                 Postgres table orders            строки
  Клиенты                Postgres table clients           строки
  Товары / услуги        Postgres table products          строки
  Фото товаров           products.image_blob              BYTEA (бинарно в БД)

  Сессии админки         admin_sessions                   токены

  Старый SQLite          ./data/crm.db                    НЕ используется

  Физически данные Postgres живут в Docker volume aigerim-landing_pgdata,
  а не в папке ./data.

4. КАК ПРИЛОЖЕНИЕ ИСПОЛЬЗУЕТ PostgreSQL
--------------------------------------------------------------------------------

  Слой доступа — crm_store.py:
    - драйвер psycopg 3
    - URL из переменной окружения DATABASE_URL
    - SQL в коде оставлен в «sqlite-стиле» (?, INSERT OR IGNORE);
      адаптер переводит в Postgres (%s, ON CONFLICT DO NOTHING)

  server.py через этот слой:
    - создаёт / читает / обновляет заказы
    - каталог товаров и отдачу фото /assets/products/<id>.ext из BYTEA
    - логин и сессии админки
    - health-check: SELECT COUNT(*) по таблицам + "storage": "postgresql"

  Запись сериализуется lock’ом DB_WRITE_LOCK.


5. СТРУКТУРА ТАБЛИЦ (кратко)
--------------------------------------------------------------------------------

  orders
    id, created_at, updated_at, source, service_id, service_name,
    message, price_from, currency, lang, status, notes,
    visitor_id, page_path, client_name, client_phone

  clients
    phone_key (PK), phone, name, note, hidden, updated_at

  products
    id, name, price, currency, kind, description, image,
    image_blob (BYTEA), image_mime, created_at, updated_at

  settings
    key (PK), value, updated_at

  order_idempotency
    key (PK), order_id → orders(id) ON DELETE CASCADE, created_at

  admin_sessions
    token (PK), csrf_token, created_at, last_seen_at, expires_at


6. БЭКАПЫ
--------------------------------------------------------------------------------

  - При старте и каждые CRM_BACKUP_INTERVAL_SEC (по умолчанию 6 часов)
    пишется файл: data/backups/crm-YYYYMMDD-HHMMSS.json.gz
  - Внутри: все таблицы; картинки — base64
  - Восстановление:
      python3 scripts/restore_pg_backup.py [путь/к/файлу.json.gz]
  - Старые crm-*.db (SQLite) — только архив миграции


7. МИГРАЦИЯ СО СТАРОГО SQLite
--------------------------------------------------------------------------------

  Выполнено:
    1) Живой data/crm.db → PostgreSQL
    2) Все data/backups/crm-*.db → дозалиты недостающие строки

  Итог: в Postgres данных больше, чем в текущем SQLite-файле
  (в SQLite осталось меньше заказов — «урезанный» снимок до очистки).

  Флаги в settings:
    sqlite_migrated = 1
    legacy_backups_merged = 1

  Plaintext-пароль (admin_password) специально НЕ переносился —
  только admin_password_hash (bcrypt).

  Скрипт повторной миграции:
    python3 scripts/migrate_sqlite_to_postgres.py [path/to/crm.db]


8. ВАЖНО ДЛЯ ЭКСПЛУАТАЦИИ
--------------------------------------------------------------------------------

  1. Не удалять Docker volume aigerim-landing_pgdata — там вся CRM.
  2. Папка ./data нужна для бэкапов; сама БД там больше не лежит.
  3. Локально без Docker: нужен Postgres + DATABASE_URL в .env.
  4. В Compose сервис web ждёт healthy db, потом стартует.
  5. data/crm.db можно держать как архив; на работу сайта он не влияет.
  6. Переменные в .env:
       POSTGRES_USER, POSTGRES_PASSWORD, POSTGRES_DB, DATABASE_URL
